# Лист «Відновлення пароля»

Firebase не дозволяє змінювати шаблони листів через API (сервісний ключ отримує `EMAIL_TEMPLATE_UPDATE_NOT_ALLOWED`),
тому налаштовується вручну: Firebase Console → проєкт **pi26-7** → Authentication → **Templates** → Password reset → олівець.

| Поле | Значення |
|---|---|
| Sender name | `Журнал старости` |
| From | `noreply@pi26-7.firebaseapp.com` (домен змінити не можна без власного домену) |
| Reply to | `noreply` |
| Subject | `Відновлення пароля в Журналі старости` |
| Customize action URL (посилання внизу форми) | `https://zhurnal-starosty.github.io/` |

Message:

```html
<p>Вітаємо!</p>
<p>Для акаунта %EMAIL% у Журналі старости надійшов запит на відновлення пароля.</p>
<p><a href="%LINK%">Встановити новий пароль</a></p>
<p>Посилання діє одну годину. Якщо ви не робили цього запиту, просто проігноруйте лист: пароль не зміниться.</p>
```

Також **Public-facing name** = `Журнал старости` (підставляється як `%APP_NAME%`) — це окреме поле, не «Project name».

Важливо: сайт **не** задає `auth.languageCode`. Якщо його задати (наприклад `'uk'`), Firebase надсилає свій вбудований
переклад («Команда pi26-7», посилання на firebaseapp.com) і ігнорує налаштований шаблон.

Посилання з листа відкриває сторінку «Новий пароль» на сайті (`js/views/action.js`, параметри `?mode=resetPassword&oobCode=...`).

## Чому лист потрапляє в спам

Лист надсилає Google від `noreply@pi26-7.firebaseapp.com` — спільного домену, з якого шлють листи тисячі проєктів;
стандартний англійський текст теж схожий на фішинг. Український текст і нормальне ім’я відправника допомагають,
але гарантовано в «Вхідні» листи потрапляють лише з власного домену (SPF/DKIM), а він платний.
Користувачу допомагає один раз натиснути «Не спам» — Gmail запам’ятовує відправника.
