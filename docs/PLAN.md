# План: журнал старости для всех групп ХНУРЕ

Сейчас: журнал для одной группы ПІ-26-7. Список студентов зашит в код, расписание загружается вручную файлом, один редактор.
Цель: любой староста регистрируется, выбирает свою группу из CIST, ведёт список студентов и отмечает присутствие;
расписание подтягивается из CIST само, по расписанию; таблицу можно выгрузить за любой период.

## 2. Архитектура

```
 CIST ──(CSV, JSON)──► GitHub Actions (cron, раз в час) ──► Firebase Realtime DB ◄──► сайт на GitHub Pages
                         Node-скрипт, ключ сервисного                                (старосты, вход по email)
                         аккаунта в GitHub Secrets
```

- **Сайт** — статический, как сейчас (HTML + CSS + JS без сборки, ES-модули), GitHub Pages из этого репозитория.
- **Firebase** — тот же проект `pi26-7`, бесплатный план Spark: Authentication (email/пароль) + Realtime Database.
  Облачные функции Firebase требуют платного плана Blaze, поэтому синхронизацию делаем через GitHub Actions.
- **Синхронизация** — workflow `.github/workflows/sync.yml`:
  - раз в сутки: справочник факультетов и групп → `/catalog`;
  - раз в час: для каждой **зарегистрированной** группы скачать CSV на весь семестр, разобрать и записать в `/schedules/{groupId}`
    (только если что-то изменилось). Незарегистрированные группы не трогаем, чтобы не нагружать CIST;
  - есть ручной запуск (`workflow_dispatch`).
- Запасной путь: если CIST что-то сломает, староста может сам загрузить CSV или XLS (импорт из текущей версии сохраняем).

### Ограничения, о которых надо знать
- GitHub запускает cron с задержкой, иногда 10–30 минут; «ровно каждый час» не гарантирован. Для расписания этого достаточно.
- В публичном репозитории GitHub отключает scheduled workflow после 60 дней без коммитов. Решение: workflow раз в месяц
  сам обновляет служебный файл (keepalive).
- CIST может поменять или закрыть CSV-экспорт так же, как закрыл JSON. Тогда остаётся ручная загрузка файла.

## 3. Модель данных (Realtime Database)

```
/catalog                      ← пишет только Actions
  updatedAt
  faculties/{facId}: {short, full, directions/{dirId}: {short, full, groups/{groupId}: "ПІ-26-7"}}
/groups/{groupId}             ← «кто староста группы»
  name, facultyShort, owner: uid, claimedAt
  deputies/{uid}: true        ← заместители (тоже редактируют журнал)
/users/{uid}
  name, email, groupId, createdAt
/schedules/{groupId}          ← пишет только Actions
  updatedAt, semester: {from, to}
  events/{eventId}: {date, start, end, subject, type, format, groups, removed?}
/journals/{groupId}           ← только владелец группы
  students/{studentId}: {name, tg, phone, note, order}
  marks/{eventId}/{studentId}: 1 (був) | 2 (не був) | {s: 2, excused: true, note: "лікарняний"}
  manualEvents/{eventId}: {...}                                          ← пары, добавленные руками
  invite: {code, createdAt}                                              ← код для заместителя
/admins/{uid}: true           ← ты, чтобы освобождать захваченные группы
```

- `eventId` стабильный: `дата_время_предмет_тип`. Отметки не теряются при обновлении расписания.
  Если пару убрали из CIST, она не удаляется, а помечается `removed` и показывается зачёркнутой (если уже есть отметки).
- `studentId` — случайный ключ, порядок задаёт поле `order`. Перестановка студентов не ломает отметки.

### Правила доступа (кратко)
- `/groups/{gid}/owner`: записать может только тот, кто вошёл, и только если там пусто (захват свободной группы),
  либо сам владелец (освободить группу), либо админ.
- `/users/{uid}`: читать и писать может только сам пользователь.
- `/journals/{gid}`: читать и писать могут только `owner` и `deputies` этой группы (и админ).
- `/catalog`, `/schedules`: читать могут все, писать никто (Actions пишет через Admin SDK в обход правил).

## 4. Функции сайта

### 4.1 Регистрация и вход
- Регистрация: email, пароль, имя → выбор группы в три шага, как на CIST: **факультет** (КН, КІІТ, ІТМ…) → **курс** →
  **группа** (по направлениям: ПІ, КНТ, ІТШІ…), плюс поиск по названию («пі-26-7»).
- Занятая группа видна, но выбрать её нельзя: «у групи вже є староста». Есть кнопка «це помилка», которая пишет админу.
- После выбора создаётся журнал, и расписание появляется после следующей синхронизации. Чтобы не ждать,
  сразу показываем «розклад завантажується» и предлагаем загрузить CSV вручную.
- Вход, выход, «забули пароль» (Firebase шлёт письмо).

### 4.2 Розділ «Студенти» (отдельная страница, без всплывающих окон)
- Таблица с редактированием прямо в ячейках: №, ПІБ, Telegram (становится ссылкой `t.me/...`), телефон (ссылка `tel:`), примітка.
- Добавить, удалить (с отменой), поменять порядок перетаскиванием или кнопками ↑↓, отсортировать по алфавиту.
- **Массовый импорт**: вставить текст (по строке на студента; ник `@tg` и телефон распознаются сами) или загрузить Excel/CSV.
  Перед применением показываем предпросмотр: что добавится, что совпало с уже существующими студентами.

### 4.3 Журнал (неделя)
- Неделя по умолчанию — текущая. Стрелки ← →, переход к любой неделе семестра.
- Пары берутся из `/schedules`, по колонке на пару: предмет, тип (Лк, Пз, Лб), время.
- Клик по ячейке: пусто → був → не був → пусто. Кнопка «всі присутні» на пару.
- У ячейки «не був» есть маленькое меню (по долгому нажатию или по значку): галочка «поважна причина» и поле
  комментария. Такая ячейка выглядит иначе (например, ✗ серым и значок комментария), комментарий виден при наведении.
- Можно добавить пару вручную, если её нет в CIST.
- Сводка: пропуски по студентам и по предметам, процент посещаемости.
- Телефон: список пар дня → по тапу открывается отметка студентов этой пары.

### 4.4 Экспорт
- Период: сегодня, эта неделя, этот месяц, весь семестр, свой диапазон дат. Дополнительно можно выбрать предметы.
- Форматы: **Excel (.xlsx)**, **HTML** (готов к печати) и **CSV**.
- Содержимое: лист «Відвідування» (студенты × пары, ✓/✗), лист «Підсумок» (по каждому студенту: был, не был,
  уважительно, %), лист «За предметами».

### 4.5 Настройки
- Изменить имя и пароль.
- **Сменить группу**: старая освобождается, новая захватывается. Журнал старой группы остаётся за ней.
  Если в нём уже есть данные, предлагаем перенести список студентов в новую группу.
- **Заместитель**: староста нажимает «запросити заступника» и получает код (например `PI267-K4F9`).
  Заместитель регистрируется, на шаге выбора группы выбирает «я заступник» и вводит код. Староста видит список
  заместителей и может отключить любого. Код можно перевыпустить, тогда старый перестаёт работать.
- Удалить аккаунт (группа освобождается, журнал удаляется после подтверждения).

## 7. Решения владельца (10.11.2026)
1. **Режима просмотра нет вообще**, в том числе для куратора. Сайт открывается окном «Вхід / Реєстрація»,
   без входа ничего не видно. Журнал группы видят только староста и заместитель.
2. **Отметки**: основной режим «був / не був». У «не був» есть дополнительная отметка «поважна причина»
   с необязательным комментарием (почему не был). В экспорте уважительные пропуски считаются отдельно.
3. **Заместитель старосты** тоже редактирует журнал. Подключается через код-приглашение (см. §4.5).
4. **Подгруппы не учитываем**: каждая пара отмечается для всей группы.
